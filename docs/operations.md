# Phase A 運営手順

## 日常

1. 作業フォルダで `npm run db:start`。
2. 2つのターミナルで `npm run dev` / `npm run worker`。
3. 画面上部がMOCKで「実際のAI試着ではありません」を表示することを確認。
4. 写真許可/18歳以上/用途と評価ケースの対応を確認。本人の許可は運営者が取得する。画像を募集投稿に使う同意は別に取る。
5. 履歴・品質・費用集計を確認。実APIunknown/reconcilingがあれば再生成しない。
6. 終了時Ctrl+C、必要ならbackup、`npm run db:stop`。公開/課金設定は行わない。

## サービス停止

`.env.local` のGENERATIONS_ENABLED=false、LIVE_API_ENABLED=false、Web/workerを再起動。新受付と未開始外部送信を拒否する。開始済みの外部ジョブは終わる可能性がある。queuedなら画面の「未開始の生成を取消」で予約解放。実行済みは取消受理と請求結果を区別する。

## 失敗と課金不明

| 状態/エラー | 行動 |
|---|---|
| queuedのまま | workerターミナルを確認、DB起動/環境変数を確認。新ジョブを乱発しない |
| PRE_SUBMIT_BLOCKED | 承認/価格/同意/停止設定に変更がないか。送信前なら予約解放 |
| RESULT_UNKNOWN / WORKER_INTERRUPTED | 実APIなら照合待ち、予約保持。POSTを再送しない |
| RESULT_TIMEOUT | 180秒超。外部実行終了を意味しない。外部IDありは読み取りpoll |
| FAL_HTTP_* / FAL_OUTPUT_HOST_UNVERIFIED / 取得不能 | 安全なHTTPステータス/理由のみを記録。外部で成功して課金された可能性。安全制約を外さず明細/外部保存を照合 |
| DB/Storage障害 | Web/workerを停止しDB volume・ディスク容量・権限を確認。画像/鍵/署名URLをログへ貼らない |

外部IDが分からない送信は自動照合できない。運営者がfalダッシュボードの利用明細/Recent History（Store-IO=0で内容保存がない可能性）と時刻/モデル/承認記録から確認し、必要なら事業者サポートへ運営者本人が問い合わせる。この実装は第三者への問い合わせを自動送信しない。外部UUIDをDBから読むのは担当エンジニアが安全に行い写真や鍵を出力しない。

確認済みの実費だけ `npm run cost:settle -- <jobUUID> <JPY整数> '<明細参照>'`。APIの成功/失敗と請求確定を分けて保持する。ID不明reconcilingの画像状態は勝手に成功/失敗へ変更しない。料金が予約を超えたら停止し予算を再判断する。実API照合の実地手順はまだ未検証。

## 写真削除

画面の履歴削除は即非表示・評価/入力/結果削除。他の生きた履歴の共有画像は残す。ファイル削除に失敗してもDBから見えなくなっただけで物理削除完了とは扱わない。停止後の全削除はREADMEのpurge手順で繰り返し実行できる。写真backupも消す。外部事業者/クラウドsnapshot/ダウンロード済み写真は別確認。実API外部削除は未実装・未確認。

## バックアップと復旧

Web/workerを止め、未完了がないことを確認。READMEのbackup/restoreを実行。backupは写真を含み、秘密鍵は含まない。暗号化ディスク上で管理。mockのみの復旧は元のジョブ/画像/評価を復元。実API履歴を含む巻き戻しは拒否するので、別の台帳保全復旧計画が必要。DBだけ/画像だけの片側復旧を無断で行わない。

## 実検証開始時の運営者操作

今は新規アカウント不要。運営者が実検証を選んだ時点で、候補モデルと料金/下流条件→初回件数・金額上限→アカウント画面の操作→鍵の安全入力→同意版→小規模実送信→明細照合の順。ログイン後の未確認のボタン名を推測で操作させない。課金ボタンは実際に表示された金額を説明して了承を得てから。Supabase/Vercel/決済はPhase B/Cで必要になってから説明する。

## Phase Aの終了判断

レポート形式は「できること/確認方法/未確認/次に必要な運営者作業」。AI品質、モデル制約、原価、worker採用理由と残課題を報告。運営者に継続/対象絞り/停止を判断してもらう。MVPへの移行をモック完成だけで自動承認しない。
