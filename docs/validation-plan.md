# 検証計画と段階のゲート

目標は2027年4月30日（日本時間）の判断。現実の参加者・請求・購入データが揃わなければ検証不足と報告する。期間は計画で保証ではない。

## Phase A（今回）

必須：入力/複数服/順序、Provider交換、永続ジョブ、同意/費用/件数ガード、評価/時間/費用、削除、migration/RLS、単体・DB・ブラウザ試験、ビルド、日本語手順。初回実API前に上限/件数/条件について運営者と合意。キーなしではモックまでとし実API未完了を明記。仕様書に基づくコード変更は許可されたが有料契約や公開は許可されていない。

| 試験 | 意味 |
|---|---|
| Vitest | 未同意/重複、API上限/カテゴリ、上限未承認、EXIF/壊れた写真、Host/Origin、モック除外、日本時間月境界、SSRF/HTTPスタブ |
| PostgreSQL統合 | 他owner拒否、NOBYPASSRLS、同時冪等、入力違い409、同時予算/件数、未開始取消、worker二重取得、送信後通信断/再送防止、クラッシュ、削除後着結果 |
| Playwright | desktopとmobile viewport Chromiumで本人/複数服/順序/生成/評価/再読込/削除。不正画像/Originも確認 |
| build/typecheck | 依存互換性とプロダクション用コンパイル |
| 運用再現 | DB開始の繰返し、停止/再開、backup→mock restore、全写真purge |

実APIテストの外部fetchはスタブ。AI画像品質/請求/外部削除はこの試験で確認しない。実機Safari/Android Chrome、Supabase Storage/RLS、実AI60ケースは未実施。0件試験を合格扱いにしない。

60ケースを同意付きで収集し40調整/20最終、Provider/モデル別品質、実API有効入力の完了率/p95、全実費、外部保護/削除を測る。PoC結果→採用モデル/worker/単価/残課題を運営者へ報告し、**運営者の判断後にのみMVP計画を示す**。モック完成だけで品質ゲートを通過しない。

## Phase B（未着手）

先に計画と商用サービス費用を提示。認証/招待/クローゼット/履歴/同意/制限/削除/運営指標。Supabase/Auth/private Storage、公開先、managed workerを料金・保持・運用条件で選定し承認後作成。AがBのAPI/DB/画像/評価/adminへアクセスできない統合試験。友人5〜10人の実機操作を行う。1月末に未安定なら追加機能凍結。

## Phase C（未着手）

再度計画・費用・決済契約・事業主体/法定表示/返金条件を確認し承認後に実購入検証。一般公開/本番決済を勝手に行わない。本人/開発者/mockを除外して友人以外の成功者50人以上に同一価格提示、14日観測、10%以上かつ5人以上の実購入。Webhook確認済み実支払だけを売上に数える。

再利用の対象は4月2日までの初回成功、28日経過した人だけ。料金提示対象は4月16日まで、14日経過した人だけ。2027年4月30日に有用80%、完了95%、p95≤180秒、再利用30%、有用性70%、粗利60%、運用2h/週、認可/削除を分母と併記して報告。必要人数未達は需要なしと断定しない。
