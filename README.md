# manyuaru — AIバーチャル試着 Phase A

2026年10月9日（日本時間）の技術PoC。本人写真・複数の服・重ね順を入力し、1枚の結果、品質評価、所要時間、費用を記録するローカル専用アプリです。調査開始時は空で `AGENTS.md` はありませんでした。Next.jsの開発起動が生成した標準の `AGENTS.md` は保持し、同梱ガイドを確認しています。既存構成の置換は行っていません。

**モック動作と実APIの品質を区別してください。** 初期状態は `MockProvider` が本人写真を返すだけです。服の合成はしません。実API接続コードはありますが、鍵なし・実送信0件で、実品質・課金・外部削除は未検証です。Phase Bの認証、クローゼット、決済、一般公開は実装していません。

## 1. 初期設定（アカウント作成・外部契約は不要）

このクラウド作業環境には Node.js 24、Docker、Chromium と依存パッケージを導入・確認済みです。ここでは新たなサービスの申し込みやカード登録は不要です。クラウド画面からの一般公開はしません。

別のPCで再現する場合の前提は Node.js 22〜24、Docker Engine 互換環境、Git。手順はLinux/macOSのターミナル、WindowsはWSLのターミナルで実行します。Docker Desktop の商用ライセンス条件は利用者の会社等で異なります。新規導入が必要になった際に、該当条件と費用を確認してから案内します。今は新規契約しないでください。

1. エディタでこのリポジトリのフォルダを開きます。この環境の場所は `/workspace/manyuaru`。
2. エディタの「ターミナル」→「新しいターミナル」を開きます。
3. 次を1行ずつ実行します。別PCでは `cd` を実際のフォルダに読み替えてください。

```sh
cd /workspace/manyuaru
npm ci
npm run db:start
```

`db:start` は名前 `manyuaru-poc-db` のローカル PostgreSQL 17 を起動し、秘密値を含まない `.env.example` から `.env.local` を作ります。ローカルDB用パスワードはランダム生成し、画面やログには表示しません。既存 `.env.local` やDBがある場合は再利用し、資格情報が失われたDBは上書きしません。001は初回にトランザクション適用、002は再実行可能な削除再試行キューです。Docker volume と `.env.local` は復旧に必要です。

## 2. モック起動と画面の操作

ターミナルを2つ開き、両方でリポジトリのフォルダへ移動します。

```sh
# ターミナル1
npm run dev
# ターミナル2
npm run worker
```

ローカルPCではブラウザのアドレス欄に `http://127.0.0.1:3000` を入力します。クラウドのオンボーディング画面はローカルアプリのプレビューに対応していないため、この作業では内部のブラウザ試験で検証しています。外部公開用URLは作成していません。

1. 「本人写真」で正面全身のJPEG/PNG/WebPを選択します。
2. 「服を追加」で複数の服を選択します。1枚10MB、2,500万画素まで。HEICは写真アプリでJPEGに書き出してください。
3. 各服のカテゴリを選び、内側/外側ボタンで順序を変えます。固定着数上限はありません。APIの制約では省略せず拒否します。
4. 写真の許可・成人・ローカル保存と、組み合わせ/重ね順を確認し、2つのチェックを入れます。
5. 「1枚生成する」を押します。モックは元の本人写真を返し、実費は0円と記録します。
6. ケース番号、調整/最終セット、採点者、3つの点数・役立ち度・問題タグ等を入力し「評価を保存」を押します。モック成績は実品質から除外します。
7. 履歴を開く、結果画像を保存、記録CSVを保存できます。再読込後も入力IDは同じタブで復元され、履歴はDBに残ります。同意は再確認します。

選択解除・入力クリアは保存画像の完全削除ではありません。履歴削除または下の全削除手順を使います。使わなかった画像も90日で削除対象となります。

## 3. 実API接続（今は実行しない）

候補は `fal-fashn`（FASHN v1.6、服1枚）と `fal-nano`（Nano Banana 2 Edit、本人含め14画像まで）。公式情報・制約・出典は [api.md](docs/api.md)。公式ページの閲覧だけを行い、課金生成・外部リソース作成は行っていません。

公式掲載料金は FASHN 1生成 **US$0.075**、Nano 1K・1枚 **US$0.08**。1ドル150円という仮計算では11.25円/12円。税、カード/為替手数料、追加出力、救済再生成は別です。falは前払クレジット方式で、最低購入額や自動チャージの最新条件はまだ確認していません。料金の詳細は [cost-model.md](docs/cost-model.md)。この数字は契約や支出の承認を意味しません。

**実APIの初回前に運営者と決めるもの**：モデル、件数上限、1件最大見積円、合計/月の円上限、為替、写真の同意と保持・学習条件、承認記録ID。仕様書のPoC予算10,000円は提案値で、承認済みではありません。

必要な鍵はサーバー専用 `FAL_KEY` 1つ。Phase AのローカルDBではSupabaseアカウント/鍵やVercel契約は不要です。今はアカウント作成や購入操作をしないでください。実検証を選んだ時点で、運営者と画面を確認しながら、公式サイトの「Sign-up」→ログイン→ダッシュボード→キー作成、料金画面の確認の順に案内します。カード入力・クレジット購入・自動チャージは費用と初回上限に合意した後です。未ログイン画面の表示名や最低購入額は推測で案内しません。

契約/条件/初回上限の確認後、ローカルPCではエディタの `.env.local` にキーを安全に入力します。クラウドでは環境設定の秘密値入力を使い、`FAL_KEY` をサーバーへ渡す方式を案内します。チャットやGitには貼りません。必要な外向き通信先は `queue.fal.run`（推論）、`rest.fal.ai`（非公開CDNトークン）、`v3b.fal.media`（結果取得）。現在の設定は公式資料の閲覧用ドメインだけを追加し、実API送信用のネットワーク・鍵はまだ設定していません。次の項目をすべて設定するまでは拒否されます。

| 設定 | 意味 |
|---|---|
| `AI_PROVIDER` | `mock` / `fal-fashn` / `fal-nano` |
| `LIVE_API_ENABLED` | 実送信のスイッチ、初期false |
| `LIVE_TERMS_REVIEWED` | 送信先・下流事業者の利用/保持/学習条件の確認 |
| `LIVE_BUDGET_APPROVED` | 初回件数・金額の運営者承認 |
| `LIVE_CONSENT_VERSION` | 運営者が実際に説明した同意文の版。画面での同意と一致が必要 |
| `LIVE_APPROVAL_ID` | 上限合意の記録ID。変更したら古い未開始ジョブは送信しない |
| `LIVE_MAX_REFERENCE_IMAGES` | 公式制約以下。FASHNは2、Nanoは14まで（服数は本人分を引く） |
| `LIVE_MAX_CALLS` | 全実API受付の累計件数上限。取消/不明/失敗も数える |
| `LIVE_TOTAL_BUDGET_JPY` / `LIVE_MONTHLY_BUDGET_JPY` | 全実APIの累計/日本時間月の円上限 |
| `LIVE_MAX_COST_JPY` | 1件の税/為替等を含む安全側の最大見積整数円 |
| `LIVE_USD_JPY` / `LIVE_PRICE_USD` / `LIVE_PRICE_CHECKED_AT` | 換算レート、公式単価、確認日 |

金額と件数の初期値は0。承認の代わりにフラグを勝手にtrueにしないでください。これは単一運営者用のガードで、予算未満の請求額をサービス側へ強制する機能ではありません。料金変更がある場合は停止・照合が必要です。

設定後はWebとワーカーを停止して再起動し、外部送信の説明を読んだうえで画面の追加チェックを入れます。実APIの応答には請求実費の証明がないため、成功でも「実費未確定」と予約を保持します。公式請求明細を照合して、以下で確定します。

```sh
npm run cost:settle -- <ジョブUUID> <確認済みの円整数> '<請求明細の参照番号>'
```

HTTP timeout、ワーカー送信中停止、結果取得失敗は照合待ちになります。自動で有料POSTを再送しません。外部IDなしの不明送信は自動復旧不能です。[運営手順](docs/operations.md) に従って明細/事業者と照合します。成功画像が公開外部CDNに返された場合も取得を拒否し、課金結果不明の予約を保持します。

## 4. 試験

```sh
npm run typecheck
npm test
npm run test:db
npm run test:e2e
npm run build
```

`test:db` は毎回ランダム所有者を使い、その所有者の試験データだけを消します。live試験のHTTPはスタブで、外部課金なし。E2Eはモック専用の端末で実行してください。実API設定に切り替えた環境でE2Eを動かしてはいけません。PlaywrightはWeb/ワーカーを起動します。既存ワーカーは先に止めてください。`build` と `dev/E2E` は `.next` を共有するため同時実行しません。

この環境は `/usr/bin/chromium` を使用。別PCでこのパスがなければ `npx playwright install chromium` で無料の試験ブラウザを導入すると自動使用します。独自のChromiumを使う場合は `PLAYWRIGHT_CHROMIUM_PATH=/実行ファイルのパス npm run test:e2e`。実機Safari/Android Chromeの確認はまだです。結果と未確認事項は [Phase Aレポート](docs/phase-a-report.md) に記録します。

## 5. 停止・削除・復旧

停止：2つのターミナルでそれぞれ `Ctrl+C`。次に `npm run db:stop`。DB停止ではvolume・画像を削除しません。生成受付だけ停止するには `.env.local` の `GENERATIONS_ENABLED=false` にしてWeb/ワーカーを再起動。実APIは `LIVE_API_ENABLED=false` も設定します。開始済み外部処理の課金は停止だけでは取り消せません。

再開：`npm run db:start` → `npm run worker` と `npm run dev`。未開始ジョブは残り、外部IDありは読み取り照合、送信済みID不明は再送しません。

個別削除：「検証履歴」→対象の「削除」→確認。入力/結果/評価は消し、他の履歴で共有中の入力と費用台帳は残します。元衣服IDの参照ではなく入力スナップショットを保持するPoCです。DBとファイルは別なので削除パスをDBに残し、ディスク障害時はワーカーが再試行します。外部AIやクラウドの既存スナップショットは別途確認します。

全写真削除：Web/ワーカーを止め、DBだけ起動した状態で次を実行します。バックアップ中の写真も削除されます。

```sh
DELETE_ALL_POC=YES npm run purge
```

写真、評価、入力/プロンプト、ローカルバックアップを削除し、費用・状態の最小台帳を残します。これにより削除で予算をリセットしません。ブラウザの「入力をクリア」またはタブを閉じて入力IDも消します。課金が不明なままDB volumeを削除しないでください。

バックアップ：未完了ジョブを処理/未開始取消し、Web/ワーカーを止めて `npm run backup`。`.backups/<日時>/` にDBと画像を保存します。鍵は含みません。写真を含むため第三者へ渡さず、暗号化ディスクで管理してください。Phase Aにはバックアップ自動化/暗号化/自動期限削除はありません。写真削除要求時はバックアップも消してください。

```sh
# モック履歴の復旧だけ対応。停止状態・DB起動中に実行
RESTORE_POC=YES npm run restore -- .backups/<日時>
```

実API履歴が現在/復旧元のDBにある場合は巻き戻しを拒否します。台帳の消失が二重課金・予算超過につながるため、照合台帳を保持する個別復旧を行います。`.env.local` の復旧は鍵を出力せず安全な別保管から行います。失われたDBを新規作成して既存予約を無視しないでください。
